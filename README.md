# VolumeKeeper

Windows のアプリ別音量を **決めた値に保つ** ための、タスクトレイ常駐ツールです。
ホットキーで開ける小さな音量ミキサーも付いています。

PC の再起動や USB オーディオ機器（USB-DAC など）の電源の入れ直しのたびに、Windows がアプリの音量を 100% に戻してしまい、通知音などが爆音で鳴る――という問題を解消するために作りました。

## 主な機能

- **音量の自動復元**
  登録したアプリ（システム音を含む）の音量セッションが新しく現れたとき、設定した音量に戻します。
  - 現れるタイミング：ログオン時、オーディオ機器の接続時、アプリの起動時
  - セッションが存在している間に手動で変えた音量は、そのまま維持します。
- **音量ミキサー**
  ホットキー（既定は `Ctrl+Shift+Q`）かトレイアイコンのクリックで開きます。
  - デバイス全体の音量と、アプリ別の音量をスライダーで調整できます。
  - マウスホイールで 2% ずつ調整、アイコンのクリックでミュートします。
  - 同じアプリの複数プロセス（Discord、Chrome など）は 1 行にまとめます。
- **設定画面**
  - 今その再生デバイスで鳴っているアプリから選ぶだけで、復元する音量を登録できます。
  - 対象の再生デバイス、ホットキー、テーマ（Windows に合わせる／ライト／ダーク）、自動起動を設定できます。
- **軽量**
  .NET Framework 4.8（Windows に標準搭載）で動き、待機中のメモリは約 25MB、CPU 使用率はほぼ 0% です。

## 動作環境

- Windows 10 / 11
- .NET Framework 4.8（Windows 10 1903 以降には標準で入っています）

## ダウンロード

[Releases](../../releases) から `VolumeKeeper.exe`（または README・LICENSE 入りの zip）をダウンロードし、好きな場所に置いて実行してください。インストールは不要です。

コード署名をしていないため、初回の実行時に Windows SmartScreen の警告が出ることがあります。その場合は「詳細情報」→「実行」で起動できます。

## ビルド

追加の SDK は不要です。Windows に付属の C# コンパイラ（`csc.exe`）でビルドします。

```powershell
.\build.ps1 -Version 1.0.0
```

`bin\VolumeKeeper.exe` ができます。`-Version` を省略すると 0.0.0 になります。

### リリース

`v1.2.3` 形式のタグを push すると、GitHub Actions（`.github/workflows/build.yml`）がビルドし、Release を作って exe と zip を添付します。main への push と PR では、ビルドの確認だけを行います。

```powershell
git tag v1.2.3
git push origin v1.2.3
```

## 使い方

1. `VolumeKeeper.exe` を起動すると、タスクトレイに常駐します。初回は設定画面が開きます。
2. 設定画面の「追加するアプリ」から、音量を保ちたいアプリを選んで音量を決め、「追加」を押します。
3. 「保存して閉じる」で保存します。以後、そのアプリの音量セッションが現れるたびに設定した音量に戻ります。

| 操作 | 方法 |
| --- | --- |
| ミキサーを開く／閉じる | `Ctrl+Shift+Q`、トレイアイコンの左クリック、`VolumeKeeper.exe --toggle` |
| ミキサーを閉じる | 画面外をクリック、`Esc` |
| 設定画面を開く | トレイアイコンの右クリック →「設定...」、起動中にもう一度 `VolumeKeeper.exe` を実行 |
| 終了 | トレイアイコンの右クリック →「終了」 |

ホットキーは、他のアプリ（EarTrumpet など）が同じキーを使っていると登録できません。その場合は設定画面で別のキーにしてください。

## 設定ファイル

設定とログは `%APPDATA%\VolumeKeeper` に保存されます。

| ファイル | 内容 |
| --- | --- |
| `volume-keeper.ini` | 設定。設定画面から編集できます。直接編集した場合も、保存すると数秒以内に反映されます |
| `volume-keeper.log` | 音量を戻した記録など。512KB を超えると `.old` に切り替えます |

```ini
# 対象の再生デバイス名に含まれる文字列（空欄なら既定の再生デバイス）
EndpointPattern=USB DAC

# 画面のテーマ（System = Windows に合わせる / Light / Dark）
Theme=System

# ミキサーを開閉するホットキー（空欄で無効）
Hotkey=Ctrl+Shift+Q

# 確認間隔（秒）
IntervalSeconds=2

# アプリ別の音量（0〜100）。キーはプロセス名（.exe なし）、System はシステム音
System=40
Discord=60
```

設定画面から保存すると、ini のコメントは定型の文に書き直されます。
読み込めない行（範囲外の数値など）は無視して、行番号と理由をログに記録し、トレイから通知します。

## 自動起動

設定画面の「Windows の起動時に自動で起動する」をオンにすると、`HKCU\Software\Microsoft\Windows\CurrentVersion\Run` に登録します。

## アンインストール

1. 設定画面で自動起動をオフにする
2. トレイアイコンの右クリック →「終了」
3. `VolumeKeeper.exe` と `%APPDATA%\VolumeKeeper` を削除する

## 制限事項

- 音量は 2 秒ごとの確認で戻すため、アプリが鳴り始めた直後の音は設定前の音量で鳴ることがあります（通常は最大約 2 秒。確認間隔の設定や処理の遅れで長くなります）。最初の音を必ず抑えられるわけではありません。
- 対象にできる再生デバイスは 1 台です。

## 仕組み

- Windows Core Audio API（`IAudioSessionManager2` など）で、再生デバイスのアプリ別音量セッションを 2 秒ごとに確認します。
- 新しく現れたセッションにだけ音量を設定します。Windows が元の値で上書きすることがあるため、6 秒後にもう一度確認し、元の値に戻されていた場合だけ設定し直します。
  - その 6 秒の間に VolumeKeeper のミキサーで操作したアプリは、再確認の対象から外します。
  - ほかのミキサー（Windows の音量ミキサーなど）で **元の値と同じ値** に戻した場合は、Windows による上書きと区別できないため、設定値に戻ります。別の値にした場合はそのまま残ります。
- 音量の設定に失敗した場合は、確認のたびに最大 5 回まで試し直します。
- 設定を保存したときは、音量の設定値を変えたアプリ（対象デバイスを変えた場合は全アプリ）にだけ適用し直します。テーマやホットキーだけの変更では音量に触りません。
- 対象の再生デバイスは 1 台です。名前が完全に一致するデバイスを優先し、なければ名前を含む最初の 1 台を使います。
- ミキサーは開いている間だけ 0.4 秒ごとに表示を更新し、閉じている間は音量オブジェクトを保持しません。
